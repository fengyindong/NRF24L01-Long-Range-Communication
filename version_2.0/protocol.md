# 阶段 1 无线协议

所有多字节整数按小端传输。联调版使用固定32字节空中载荷，逻辑帧后的剩余字节补零。

## 帧布局

| 字段 | 字节 | 说明 |
|---|---:|---|
| magic | 2 | 固定 `0x4E52` |
| version | 1 | 当前为 1 |
| type | 1 | 消息类型 |
| network_id | 2 | 当前为 `0x2026` |
| src_id | 2 | 主机 0，从机 1 |
| dst_id | 2 | 目标 ID |
| boot_id | 2 | 每次启动生成/递增的启动标识 |
| seq | 2 | 发送方向递增序号 |
| payload_len | 1 | 0~14 |
| flags | 1 | 保留 |
| payload | 0~14 | 类型相关数据 |
| CRC16 | 2 | CRC-16/CCITT-FALSE，覆盖前面全部有效字节 |

消息类型：

- `0x01 POLL`：主机请求最新快照。
- `0x02 TELEMETRY`：从机返回模拟遥测。
- `0x10 COMMAND`：主机下发命令。
- `0x11 COMMAND_ACK`：从机返回应用层执行结果。

命令码：`1 SET_LED`、`2 SET_SAMPLE_PERIOD`、`3 FORCE_SAMPLE`、`4 DEBUG_DUMP`。

## 可靠性规则

1. nRF 硬件自动 ACK/重发只表示当前射频包被对端芯片收到。
2. 主机发送请求后切到接收模式，等待对应应用层响应。
3. 响应必须匹配网络、源/目标、请求类型；遥测回显 `request_seq`，命令回显 `command_id`。
4. 主机超时后最多重发同一个逻辑请求；重发保持原 `seq` 和 `command_id`。
5. 从机以 `(master_boot_id, request_seq)` 识别重复请求。重复命令不再次执行，而是重发缓存的响应。
6. MQTT重投递即使产生新的无线请求序号，从机仍以`command_id`识别重复业务命令并返回历史结果。
7. CRC、长度或身份不合法的帧不会更新在线时间。

## 射频地址

- 主机接收地址字节：`D2 D2 D2 D2 A0`
- 从机 1 接收地址字节：`E7 E7 E7 E7 01`
- 首次联调频道：76（`2476 MHz`），速率：1 Mbps

ESP8266 Wi-Fi 启用后应根据固定 Wi-Fi 信道和现场 `PLOS_CNT` 重新选择频道。
